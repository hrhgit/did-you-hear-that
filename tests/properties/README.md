# tests/properties

Property-based tests written with fast-check and run by Vitest under Node. Files are named `*.property.test.ts`.

When a property finds a counterexample, fast-check prints its seed and the shrunk case. Keep that case as a named regression test, and put the fix in a separate commit.

- **`checks/`** holds one module per correctness property of the threshold search, shared by the Vitest files and by `npm run experiment:properties`, which writes `docs/experiments/brief-properties-<search>.json`. Modules marked harness-neutral run against any search through `tests/listeners/search-under-test.ts`. The others check this repository's own engine only. `ear-oracle.ts` re-derives an ear's result from its trial records without calling the engine.
- **The regression file.** `threshold-search-regressions.test.ts` holds one case per counterexample, named `regression <n>: <what went wrong> (<property>, seed <s>)`, with hard-coded listener parameters and seeds. A case is first committed on its own, marked in Vitest as a test that is expected to break, which keeps the suite green. The commit that changes the code turns it into an ordinary `it`. A case whose only remedy would move a value that may not be moved silently stays an expected break, with a decision in `.kiro/specs/threshold-search/design.md` giving the measured numbers.
- **Seeds.** Universal properties run with a new random seed every time, so each run explores new cases. Statistical properties, which judge rates over many simulated rooms, run with fixed seeds and fixed limits, so a change in their verdict comes from the code and not from the draw.

## The visit flow

The properties CP1 to CP11 of `.kiro/specs/visit-flow/design.md` are in `visit-flow-cp<n>-*.property.test.ts`. Each plays whole visits through the visit flow under Node, with no browser.

- **The visit harness.** `visit-flow-harness.ts` (`createVisitHarness`) builds a visit flow on the fake audio backend and the manual timer. The page clock runs ahead of the audio clock by an offset drawn per run, from 0 to 10⁶ ms, so that no code can assume the two are equal, and the harness moves both clocks together. It records every snapshot notification and event with its time and its cause (an action, a stop report or a timer callback), every presented trial, every action, and every `schedule` call on the backend. With `spyOnOutput` it also wraps the output shell in a spy that records the flow's calls to it. The files that use it replace the synth's render functions with the worst-case renderers of `worst-case-renderers.ts` through `vi.mock`, so a visit takes milliseconds. `visit-flow-timeline.ts` (`observeVisit`) puts the harness's separate records in one ordered list, with the snapshot before and after each action and stop report, for the properties that ask what came before what.
- **The visitor scripts.** `visit-flow-arbitraries.ts` draws what a simulated visitor does in one visit: the visit type, a calibration target, the first answer to the headphone check, a listener (psychometric, one of the extreme listeners, or any function of the trial), answer delays that sometimes fall after the window, time stamp modes, extra presses, up to four pauses or stop reports each followed by a resume, at most one ending, and rests of up to 30 s before each step on. `tests/listeners/simulated-visitor.ts` plays the script.
- **Simulated visits.** `visit-flow-simulated-visits.test.ts` plays a quick and a full visit to the result with fixed seeds, for an attentive and a plausible listener and for each extreme listener.
- **The regression file.** `visit-flow-regressions.test.ts` holds one case per counterexample a visit flow property finds, named and handled as in the regression file of the threshold search above. A case that only a change of a steering value or of the proposed visit limit (Q1) could remove stays an expected break. It holds one `it.todo` until the first case is found.

## The result page

The properties CP1 to CP9 of `.kiro/specs/result-page/design.md` are in `result-page-cp<n>-*.property.test.ts`. They run under Node on the pure picture model and on archives over the fake storage area of `src/storage/fake-storage-area.ts`, with no browser and no real local storage. Their run counts are those of the design's "Run counts and time", each with a new random seed on every run, and the times of three runs are written there. Their budget is 30 seconds together, decided on 2026-11-15 on the owner's behalf, at the owner's request with the run counts (Q7).

- **CP1, safe wording.** No string of a picture, a list or an outcome, and no string exported from the result page's copy, holds a banned term, except the two allowed terms in the four sentences of the limits statement; every picture holds the limits statement itself; every level is labelled relative to the calibration or is a left and right difference; no string speaks of accuracy, is empty or has white space at its ends; and no generated string holds a name the visitor typed.
- **CP2, no text compares floors.** A floor's strings name only its own room and pitch, the strings outside the floors name none, no string but the limits statement holds a word of comparison once the allowed forms are removed, every number is one the design allows in its place, and the floors are in the order of the house.
- **CP3 and CP4, the picture.** CP3 checks how far the light reaches on any floor's scale and that every wing of a picture is drawn on its own floor's scale. CP4 replaces every other floor of a visit, keeping the visit-level marking, and checks that a floor stays as it was.
- **CP5 to CP8, saved visits.** CP5 saves up to 8 drawn visits, some again, and reads them back as they were saved, newest first. CP6 deletes listed and unlisted ids and all, among unreadable entries and other keys of local storage, and checks that exactly what was asked went. CP7 changes the value an archive wrote and makes local storage refuse in every way, and checks that nothing throws, that every listed visit is one that was saved, and that a refused or full write changes nothing. CP8 checks that robot mode never calls for local storage.
- **CP9, the earlier visit.** CP9 draws lists of saved visits whose headphone names are written in any letter case, spacing and Unicode form, and checks that `findEarlierVisit` gives the newest visit saved before the shown one with the same name, and never the shown visit. Whether two names are the same is known from how they were drawn, not from the code under test. It then draws a picture with any earlier visit and checks that a wing has the earlier visit's mark exactly when the earlier visit entered its room, that the outline is on the shown floor's own scale and missing for an unreliable earlier ear, and that the comparison line names the earlier visit. CP1 and CP2 also draw an earlier visit or none.
- **The arbitraries.** `result-page-arbitraries.ts` draws visits as hand-built visit logs whose summaries come from `summarizeVisit` itself, so every summary has the invariants the visit flow gives it: rooms in any of the four states on the 5 dB grid, any search reasons, sometimes an abandoned first run or a sound played at another level than asked, few false alarms more often than many, and a visit limit from 0.05 to 0.30. The picture properties also draw the swapped-repeat difference from 5 to 30 dB; the storage properties use the shipped one, because that is the one the archive saves. It also draws picture inputs, live or saved with a `floorDb` from −80 to −40 and a date from 2026 to 2030; typed headphone names, each holding a word that occurs in no string of the house, with any spacing, letter case, control characters and combining marks, at the length limit and one past it; list scenarios for CP1 and CP2, which cover every list state and every reason a save or a delete is refused; values an archive wrote and then changed (a character replaced, removed or inserted, the text cut off, two entries swapped, a field replaced, the format version changed, the whole value replaced); storage behaviours (working, no local storage, reading refused, writing refused, and a quota of any size); and, for the comparison, earlier visits of either visit type and headphone names made from a fixed set of names.
- **The text helpers.** `result-page-text.ts` collects every string of a picture, a list and an outcome with its place, and holds the allowed forms and word lists of CP1 and CP2.
- **Simulated visits.** `result-page-simulated-visits.test.ts` plays a quick and a full visit to the result through `visit-flow-harness.ts` and `tests/listeners/simulated-visitor.ts`, with fixed seeds, a Plausible_Range listener and the worst-case renderers, saves both through one archive, reads them back as the result snapshot gave them, exports their logs and draws each as a live and as a saved picture. The sizes of the stored value it gives are written in the design under "Measured sizes".
- **The regression file.** `result-page-regressions.test.ts` holds one case per counterexample a result page property finds, named and handled as in the regression file of the threshold search above. A case that only a change of a steering value or of a value decided in Q1, Q4 or Q5 could remove stays an expected break. It holds one `it.todo` until the first case is found.

The `screen-leak/` folder has its own README, `screen-leak/README.md`.
