# src/storage

Reading and writing past visits in the browser's local storage, under a versioned key. Nothing leaves the browser.

May import from: `config`.

## The visit store

The store keeps the visits the visitor chose to save. The design is in `.kiro/specs/result-page/design.md`, "The stored format". `src/session` reaches the store through the visit archive; `src/ui` never imports this module.

- **One key and one value.** `saved-visits-key.ts` holds the key, `did-you-hear-that:saved-visits:v1`, and the format version, 1. A site on `github.io` shares its origin, and so its local storage, with the other project pages of the same account, so the key carries the product's name. The `v1` names the format of the value. A later format that this code cannot read will use a new key, which this code never touches. The value is JSON text: the format version and the list of saved visits in the order they were saved, oldest first.
- **The envelope and the payload.** Each entry holds a saved visit id of eight lowercase hexadecimal digits, the time it was saved in epoch milliseconds, the visitor's local date, the visit type, the tidy headphone name or null, the payload as JSON text, and a checksum. This module may import only `config`, so it cannot know the visit log. It keeps the payload as text and never reads what is in it. `src/session` writes the payload and checks it when it reads it back.
- **The checksum.** `entry-checksum.ts` (`entryChecksum`) is the 32-bit FNV-1a hash over the JSON text of the entry's six other fields, written as eight lowercase hexadecimal digits. It makes accidental damage visible: a cut-off write, a changed character, a hand edit that forgets it. It does not protect against a deliberate edit, because anyone who edits local storage can compute it again.
- **Unreadable entries.** An entry with a missing or mistyped field, an id that is not eight lowercase hexadecimal digits, an id that an earlier entry already uses, a date that is not a calendar date, a visit type other than `quick` or `full`, or a checksum that does not match is unreadable. It is counted and not shown, and every write keeps it as the same JSON value, until "delete all" removes the key.
- **Unreadable values.** A value that is not JSON, not a plain object, of another format version, or without a list of entries is unreadable as a whole. The store then lists nothing, writes nothing when asked to add, rename or remove one entry, and removes the key only when asked to remove everything. A save never writes over such a value, because that would delete whatever it holds.
- **`create-visit-store.ts`.** `createVisitStore` reads the value again before every change and writes the whole new value with one `setItem`, keeping every other entry and every field it does not know as it read them. It removes the key when no entry and no unknown field is left. It calls the function that gives local storage inside a `try` at every method, reads and writes no other key, keeps nothing between calls, and never throws because of anything local storage does or holds. Two tabs that save in the same moment can still overwrite one another's entry; reading just before writing keeps that window short. `visit-store-types.ts` holds the store's types, and `storage-area.ts` the three methods of the browser's `Storage` that it uses.
- **`changePayload`.** `changePayload(savedVisitId, payloadJson)` gives one entry a new payload and a new checksum, keeps its id, its dates, its visit type, its headphone name, its place and every other entry as they were, refuses as `changeName` does, and is how the archive saves a visit again with its swapped repeats (`.kiro/specs/swapped-repeat/design.md`, Q5).
- **The failure names.** `unavailable`: the browser gives no local storage, or reading it throws. `full`: a write met the quota. `refused`: a write or a removal threw anything else, such as a security setting. `unreadable`: the value cannot be read as a whole. `notFound`: an entry to rename or remove is not there. `idTaken`: a new entry's id is already in the value. `storage-error-kind.ts` (`storageErrorKind`) tells `full` from `refused` by the error names and codes that Chrome, Safari and Firefox use for a full quota. A write that is refused or full leaves the stored value as it was.
- **The fake storage area.** `fake-storage-area.ts` (`createFakeStorageArea`) is an in-memory storage area for the tests in `src/storage`, `src/session` and `tests/`. It can start with any keys and values, hold a limited number of characters, refuse to read, to write or to remove, and it records every call. No test touches a real local storage.

Nothing this module keeps is sent anywhere: there is no network request, no cookie, and no storage other than local storage under the one key.
